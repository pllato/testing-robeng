# Кубики — проект

Приложение для детей и родителей: **сфотографировал кучу кубиков → получил список игрушек, которые собираются именно из этих деталей → собрал по шагам**. Ничего докупать не нужно, каждый запуск даёт новую игрушку из того же ящика.

Клиент: `app/bricks.html` — HTML-страница без сборки. Распознавание: `bricks-api/`, Cloudflare Worker с Workers AI (Gemma 4 Vision).
Адрес: `https://pllato.github.io/testing-robeng/app/bricks.html` (открывать с телефона: камера работает только по HTTPS).

---

## 1. Сценарий

1. Ребёнок высыпает коробку с деталями на ковёр в один слой.
2. Родитель снимает кучу сверху → приложение считает детали (Cloudflare Workers AI, vision) → список можно поправить руками.
3. Приложение показывает, что собирается **прямо сейчас**, а что — с нехваткой («не хватает 2 деталей: 2x4, 1x2»).
4. Сборка по шагам: на картинке детали текущего шага обведены, рядом список «возьми: 1 × красный 2x4».
5. Не можете найти кубик в куче — «🔎 Найти»: камера подсвечивает детали нужного цвета и пишет «горячо / холодно».
6. «🎲 Сюрприз» — случайная игрушка из доступных, с приоритетом ещё не собранных.

Ручной ввод деталей заменяет шаг 2 целиком, поэтому **ключ на телефоне не требуется; без сети доступны ручной ввод и сборка**.

## 2. Экраны — одна главная кнопка

Обновление 2026-09-29: одна постоянная главная кнопка внизу, без нижних вкладок. Наверху только возврат, логотип и тихий вход «Родителям». Светлый фон, фиолетовый акцент, реальные canvas-модели игрушек. Анимации отключаются при prefers-reduced-motion; масштабирование страницы разрешено.

| Экран | Основное действие |
|---|---|
| Главная | «Начать волшебство», при наличии инвентаря — «Что соберём сегодня?» |
| Фото | «Сфотографировать кубики»; после выбора снимка распознавание запускается автоматически, кнопка показывает ожидание |
| Результат | «Выбрать игрушку» сохраняет распознанный набор как текущий; подробный список и исправления раскрываются со взрослым |
| Нет результата / ошибка | «Снять другое фото», понятная подсказка остаётся на экране |
| Идеи | Одна крупная модель из доступных, неброские стрелки выбора и кнопка «Собрать…»; если ничего не подходит — «Показать кубики» |
| Сборка | Крупная иллюстрация, прогресс, количество и размеры нужных кубиков; «Получилось! Дальше» или «Готово! Это я собрал!»; поиск спрятан в раскрываемую помощь |
| Готово | Готовая модель, поздравление, «Ещё одно приключение» |
| Родителям | Ручной инвентарь, новая фотография, демонстрационный набор, история и информация об обработке фото |

Проверено в Chromium на ширинах 320, 390 и 1024 px: старт, автоматический запрос, сохранение результата, выбор модели, все шаги первой модели, поздравление, повторная сборка, пустой результат и возврат в ручной инвентарь. HTTP-ответы для проверки UI подменялись; серверный API не менялся.

## 3. Как устроено внутри

### Данные

Всё в `localStorage`, ключ `bricks_v1`:

```js
{
  inv: { "red|2x4": 6, "white|1x2": 4, ... },  // инвентарь: "цвет|размер" → количество
  built: ["duck", "car", "duck"],              // история собранного
  color: "red",                                // выбранный цвет на экране «Детали»
  filter: "all",                               // фильтр на экране «Идеи»
}
```

Цвета — 12 штук (`COLORS`), размеры — 7 (`SIZES`: `1x1`, `1x2`, `1x3`, `1x4`, `2x2`, `2x3`, `2x4`).
Ключ размера всегда «меньшее × большее», поэтому кубик 4x2 и 2x4 — одна и та же строка инвентаря.

### Подбор: хватает ли деталей

`planModel(model)` считает требуемые детали из шагов модели и «выдаёт» их из инвентаря, начиная с самых крупных. Если детали нужного размера нет, работает замена (`SUBST`, рекурсивно, до 3 уровней):

```
2x4 → 2x2 + 2x2  или  2x3 + 1x2
2x3 → 2x2 + 1x2
2x2 → 1x2 + 1x2
1x4 → 1x2 + 1x2  или  1x3 + 1x1
1x3 → 1x2 + 1x1
1x2 → 1x1 + 1x1
```

Возвращает `{need, missing, ok}`. На карточке идеи показывается `missing` — чего и сколько не хватает.

Подбор **цветослепой**: считается только форма. Это сделано намеренно — у ребёнка в ящике редко лежит ровно тот цвет, что «по задумке».

### План цветов

`colorPlan(model)` раздаёт слотам модели (`A`, `B`, `C` — это роли: корпус, акцент, детали) реальные цвета из инвентаря:

- слоты с бо́льшим числом деталей выбирают первыми;
- цвет оценивается по тому, сколько нужных размеров он покрывает (с теми же заменами);
- +0,35 к оценке цвету «по задумке», −0,5 цвету, уже занятому другим слотом.

Поэтому одна и та же машинка у разных детей (и в разные дни) выходит разного цвета — это и даёт эффект «каждый раз новая игрушка».

### Рендер инструкций

`drawScene(canvas, bricks)` — изометрия на 2D canvas, без библиотек:

- проекция `x_экр = (x−y)·0.866`, `y_экр = (x+y)/2 − z·1.15`;
- сначала считается bounding box всей сцены в условных единицах, потом подбирается масштаб под размер холста — поэтому и уточка из 6 деталей, и маяк в 6 этажей влезают целиком;
- порядок рисования: сначала дальние (меньше `x+y`), внутри — снизу вверх;
- у каждого кубика три грани (верх, и две боковые с затемнением 0,8 и 0,62) плюс шипы **поверх** верхней грани;
- детали текущего шага обводятся оранжевым (`flash`), уже собранное рисуется обычным цветом.

### Искалка

`loopFinder()` каждый кадр:

1. рисует кадр видео в скрытый canvas 96×128 (мелко — чтобы хватало на слабом телефоне);
2. считает пиксели, близкие к целевому цвету: евклидово расстояние в RGB **и** отдельно близость по яркости — второе отсекает бежевый ковёр и дерево стола, которые по RGB похожи на оранжевый и коричневый;
3. порог зависит от цвета (`colorThreshold`): у белого/чёрного/серого он жёстче;
4. по центру масс попаданий рисует пунктирную рамку и пишет статус: «Вот он», «Горячо», «Холодно».

Нет камеры или не дали доступ — экран не ломается: предлагается «Показать деталь» с крупной картинкой нужного кубика.

### Распознавание по фото

Клиент отправляет сжатое фото в `POST https://bricks-recognition.uurraa.workers.dev/recognize`:

- тело `{image: "base64", mime: "image/jpeg"}`;
- Worker вызывает `@cf/google/gemma-4-26b-a4b-it` через binding `AI`;
- ключи и SDK AI-провайдера на телефоне не нужны; старый ключ удаляется из localStorage без удаления инвентаря;
- ответ `{items: [{color, size, count}], note}` проверяется на сервере и клиенте; цвета и размеры ограничены каталогом, количество — целое от 1 до 99;
- пустой список — допустимый результат: клиент предлагает переснять несколько обычных кубиков отдельно;
- ограничение тела 4 MB, проверка MIME и сигнатуры изображения, таймаут AI 80 секунд и клиента 90 секунд;
- CORS для `https://pllato.github.io`, ограничения 4 запроса в минуту с IP и 20 в минуту суммарно в каждой локации Cloudflare. Это не авторизация и не жёсткий глобальный бюджет;
- снимки не сохраняются приложением, содержимое фото и ответов модели не пишется в логи;
- двойное нажатие не создаёт второй запрос; смена фото отменяет ожидание старого результата;
- текст ответа выводится с HTML-экранированием.

Подробности развёртывания и проверок — `bricks-api/README.md`.

## 4. Каталог моделей

Сейчас 10 штук: уточка, машинка, кораблик, собачка, самолётик, домик, ракета, пингвин, робот, маяк.

Модель — это только список кубиков по шагам, всё остальное (какие детали нужны, сколько их, сколько шагов) считается автоматически:

```js
{
  id:'car', name:'Машинка', emoji:'🚗', age:'4+', level:1,
  slots:{ A:'red', B:'black', C:'azure' },   // «задуманные» цвета ролей
  about:'Едет, если подтолкнуть.',
  steps:[
    { t:'Днище',  bricks:[ b(0,1,0, 4,2, 'A') ] },
    { t:'Колёса', bricks:[ b(0,0,0, 1,1,'B'), b(3,0,0, 1,1,'B'),
                           b(0,3,0, 1,1,'B'), b(3,3,0, 1,1,'B') ] },
    ...
  ]
}
```

`b(x, y, z, w, d, слот)`: `x` — вправо, `y` — вглубь, `z` — этаж (снизу вверх, 0 — пол), `w×d` — размер в шипах.

**Как добавить модель:** дописать объект в массив `MODELS` и прогнать проверку геометрии (см. ниже). Больше ничего менять не нужно — карточка, подсчёт деталей, шаги и картинки появятся сами.

Два правила, которые проверяются автоматически:

1. кубики на одном этаже не должны пересекаться по площади;
2. каждый кубик выше нулевого этажа должен хотя бы частично опираться на кубик этажом ниже.

## 5. Что проверено

Прогон в Chromium (Playwright), файлы тестов лежат вне репозитория:

- **геометрия всех 10 моделей** — нет пересечений и висящих в воздухе деталей;
- **подбор** — на пустом инвентаре не предлагается ничего; на демонаборе из 51 детали собираются все 10 моделей, состав деталей каждой выводится в отчёт;
- **все шаги всех моделей** пройдены вперёд-назад без ошибок в консоли;
- **цветовой поиск** — красный кубик (в том числе в тени) ловится, бежевый ковёр, дерево стола, синий и розовый кубики — нет;
- **камера** — на тестовом устройстве Chromium цикл разбора кадров работает и обновляет статус;
- **поведение без ключа и без камеры** — понятные подсказки вместо ошибок.

Эти проверки поймали четыре реальные ошибки до выкладки: у самолёта крылья висели в воздухе, у машинки колёса пересекались с днищем, у домика/ракеты/маяка основание требовало деталь 4x4 (такой нет в списке размеров — модели не собрались бы никогда), а в рендере шипы рисовались под верхней гранью и высокие модели вылезали за край картинки.

**Проверено 2026-09-29:** живой вызов Cloudflare Workers AI на предоставленном пользователем скриншоте: HTTP 200 за ~10 секунд, пустой список (подходящие детали в куче не определены достаточно уверенно). Это проверка подключения, а не подтверждение точности распознавания.

## 6. Ограничения

- Счёт деталей по фото всегда приблизительный: кубики лежат друг на друге и частично перекрыты. Поэтому правка списка руками — часть сценария, а не костыль.
- Распознавание использует квоту/тариф Workers AI аккаунта владельца. Ключ от пользователя не требуется (одно фото — один запрос с картинкой).
- Поддерживаются только обычные прямоугольные кубики. Скосы, колёса, фигурки, пластины (тонкие детали) не считаются и в моделях не используются.
- Искалка ориентируется на цвет, а не на форму: она покажет, где лежат красные детали, но не отличит красную 2x4 от красной 2x2.
- Приложение не связано с компанией LEGO®. Модели придуманы для сборки из кубиков любого производителя.

## 7. Что можно сделать дальше

- **Больше моделей** — самое дешёвое улучшение: каждая новая модель это ~10 строк.
- **Учитывать цвет в подборе** как мягкое предпочтение: сейчас «все детали одного цвета» и «сборная солянка» оцениваются одинаково.
- **Размер вместо цвета в искалке** — определять прямоугольники и считать шипы, чтобы отличать 2x4 от 2x2.
- **Свои модели** — конструктор, где родитель раскладывает кубики по сетке и сохраняет инструкцию для ребёнка.
- **Качество распознавания** — проверить на размеченных фото обычных кубиков в один слой; расширять поддержку деталей только после проверки качества.
- **Печать инструкции** в PDF — как в Робенге, чтобы собирать без телефона.
